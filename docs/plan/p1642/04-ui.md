# 04 - UI design: parity features, planning view, live progress

Role: Designer. Planning only, no code changed. Scope: the NotionTool layer inside the Notion
desktop sidebar (`notiontool/web/desktop/`). Builds on what exists today: `shell.js/.css` (tab bar,
router, view layer), `overlay.js/.css` (brand row, Mains card, Coworkers), `live.js/.css`,
`progress.js/.css`, `notes.js/.css`, `settings.js/.css`, `theme.css` (tokens).

## 1. Goals and rules

- One home for every old-app feature: MCP servers, accounts, coworkers, runs/reports, backups,
  git, problems. Nothing needs the old web app any more.
- A planning view: who plans what, review, final plan, approve.
- Live coworker progress from NotionTool's own state (store/events). Never opens or loads a
  coworker chat to show progress.
- Premium and calm, clearly not Notion: a deep blue-black surface, one violet accent, dense
  but airy rows, no Notion grey, no emoji icons.
- No clutter: at most 4 tabs, at most one badge per tab, one status dot per row, no repeated
  numbers (each count is shown in exactly one place).
- Hard rules kept: DOM only via `ctx.el`/`textContent`, never remove Notion nodes, no network
  calls to Notion from the page (data comes from the local NotionTool API the page already
  uses), all UI text English, the Notion footer (`New chat Ctrl+O`) is never covered.

## 2. Information architecture

Sidebar, top to bottom (width = Notion sidebar width, typically 240-300 px):

```
+-------------------------------------------+
| [N] NotionTool   (o Live)   [bell] [gear] |  Header row, 40 px
| Chat | Live | Plan | Ops                  |  Tab bar, 36 px, directly under the header
|-------------------------------------------|
|  active view (scrolls)                    |
|-------------------------------------------|
| Notion footer: New chat  Ctrl+O           |  untouched, always visible
+-------------------------------------------+
```

| Tab | Contains | Badge (one number, accent pill) |
|---|---|---|
| Chat | Notion's own chat list, unchanged | Notion unread chats |
| Live | Main status card, coworker live list, current run strip | coworkers that need attention (stalled, failed, waiting for confirmation) |
| Plan | Planning phase of the current request: planners, drafts, review, final plan | plan items waiting for the user (approve / answer) |
| Ops | Sections: Problems, Runs and reports, Accounts, MCP servers, Git, Backups, Notes | open problems |

- Settings moves out of the tab bar to the gear icon in the header (opens the existing settings
  view in the layer). This frees the slot for Plan without a fifth tab.
- Notes becomes the last Ops section (rarely used; its view stays unchanged).
- Bell = event/toast history (existing). Live pill = connection state (existing).
- Keyboard: arrows/Home/End/Enter across the 4 tabs (already in shell.js).

## 3. Design tokens

Use the existing variables in `theme.css`; add only what is missing. All views use these
tokens, never raw colors.

### Color

| Token | Value | Use |
|---|---|---|
| `--nt-bg` | `#0b0d12` | layer background (view area) |
| `--nt-surface` | `#12151d` | cards, section bodies, tab bar |
| `--nt-raised` | `#181c26` | hover, active row, inputs, progress track |
| `--nt-border` | `rgba(255,255,255,.07)` | 1 px hairlines, card borders |
| `--nt-text` | `#e8eaf2` | primary text |
| `--nt-muted` | `#9aa3b8` | secondary text, labels |
| `--nt-faint` (new) | `#646c80` | timestamps, disabled, queued ring |
| `--nt-accent` | `#7c5cff` | the only accent: active tab, primary button, badges, focus ring, progress fill |
| `--nt-accent-soft` (new) | `rgba(124,92,255,.14)` | selected row, active section background |
| `--nt-success` | `#22c55e` | status dot / outline pill only |
| `--nt-warning` | `#f59e0b` | status dot / outline pill only |
| `--nt-danger` | `#ef4444` | status dot, destructive button text |

Rules: status colors appear only as 8 px dots, outline pills or 2 px left bars, never as filled
cards. The violet-to-cyan gradient is retired from all UI except the 20 px brand mark. No cyan
as a second accent.

### Type

- Font: `Inter, "Segoe UI Variable", "Segoe UI", system-ui, sans-serif`; numbers use
  `font-variant-numeric: tabular-nums`. Paths, file names, commit ids, task ids:
  `"Cascadia Mono", Consolas, monospace`.

| Role | Size / line height | Weight | Color |
|---|---|---|---|
| Section title | 11 / 16 px, uppercase, letter-spacing .06em | 600 | muted |
| Row title | 13 / 20 px | 500 | text |
| Row meta | 12 / 16 px | 400 | muted |
| Card title | 14 / 20 px | 600 | text |
| Tab label | 12 / 16 px | 600 | muted, active white |
| Mono | 12 / 16 px | 400 | muted |

### Spacing, radius, motion

- 8 px grid: allowed values 4 (only inside controls), 8, 16, 24, 32.
- View padding 8 px left/right; 16 px between sections; 8 px inside cards.
- Row height 32 px (one line) or 48 px (two lines). Tab bar 36 px, header 40 px.
- Radius: 8 px for cards, rows, buttons, tabs; 999 px only for pills and dots.
- Shadows: none inside the sidebar. Popovers/menus only: `0 8px 24px rgba(0,0,0,.45)`.
- Motion: 120 ms ease-out for hover/active, 200 ms for expand/collapse; with
  `prefers-reduced-motion` no animation (progress bars jump, no pulse).

## 4. Components

All new components use a `nt-ui-*` class and are built with `ctx.el`.

1. **Tab** (exists): 36 px bar, 4 equal tabs. Active: accent fill, white text. Inactive:
   transparent, muted, hover raised. Badge: accent pill 16 px high, min-width 16, 11 px text;
   on the active tab it inverts (white pill, accent text).
2. **Section**: 32 px title row with chevron and an optional muted count on the right (no
   pill). Collapsible; state stored in `localStorage` as `ntDesk.section.<id>`.
3. **Row**: 32/48 px, 8 px padding, radius 8. Left: 8 px status dot. Middle: title + meta, one
   line each with ellipsis, full text in `title`. Right: exactly one trailing element (time,
   count, or a 24 px icon button shown on hover/focus).
4. **Card**: surface, 1 px border, radius 8, padding 8. For Main card, plan items, run strip.
   No nested cards.
5. **Status dot** (8 px): running = accent with 1.6 s pulse; done = success; waiting for the
   user = warning; failed/stalled = danger; idle = faint; queued = faint hollow ring.
6. **Progress bar**: 4 px, radius 999, track raised, fill accent; text next to it is always
   `n of m`, never percent.
7. **Buttons** (28 px high, radius 8, 12/16 600): primary = accent fill, white; secondary =
   raised fill, text color; ghost = no fill, muted, hover raised. Destructive = secondary with
   danger text plus inline confirm. Max one primary button per view.
8. **Pill** (verdict/state): 20 px, 1 px outline in the status color, text in the status color,
   11 px 600.
9. **Switch**: 28x16 px, track raised, on = accent, white 12 px knob.
10. **Empty state**: one muted line plus at most one ghost button, 32 px top margin. No
    illustrations.
11. **Inline confirm**: the row expands with "Confirm" (primary) and "Cancel" (ghost). No modal
    dialogs in the sidebar.
12. **Toast** (exists): bottom of the layer, above the Notion footer, auto-hide 4 s, max 2.

### Shared states

| State | Look |
|---|---|
| Hover | row background raised |
| Focus (keyboard) | 2 px accent outline, offset 1 px, radius 8 |
| Selected | accent-soft background + 2 px accent left bar |
| Disabled | faint text, no hover, `aria-disabled="true"` |
| Loading | 3 skeleton rows (raised blocks, radius 8, no shimmer); no spinner over content |
| Offline (no local API) | one warning row at the top: "NotionTool is not reachable - retrying"; old data stays visible at `opacity .6` |
| Section error | title stays; body shows one danger-dot row with a short reason and a "Retry" ghost button |

## 5. Views

### 5.1 Live (coworker progress without loading chats)

Data: only the local state the page already gets (workers, runs, tasks, events) through the
existing state subscription. No extra request per coworker, never a Notion transcript read.

```
MAIN
[card] o Main - Fixing tests - 2 of 3 done
       ==========-----   2 of 3        4 min
COWORKERS                               3
 o Designer   Writing UI spec          1m
 o Engine     Waiting for review       3m
 o Speed      Idle
RUN
[card] Plan p1642 - planning   ===---  1 of 4
```

- Main card: line 1 = short status (`<phase> <topic> - n of m done`), ellipsis, full goal in
  `title`. Line 2 = progress bar + `n of m` + elapsed time.
- Coworker row: dot, name (role or account label), current task title or `Idle`, right side =
  time since last change. Click expands inline: last 2 event lines from the store (for example
  "Ran tests - 72 passed"), then `Open chat` (ghost; opens the Notion chat only on this
  explicit click) and `Stop` (destructive, inline confirm).
- Order: needs attention (danger, warning) first, then running, then idle. Max 8 rows, then
  "Show all (n)". Only coworkers of the active account.

### 5.2 Plan (planning phase)

Shows the plan-first mode from `02-plan-mode.md` (stages Draft -> Review -> Final -> Approve,
then Running). Display only; the view never edits plan files.

```
Draft ---- Review ---- Final ---- Approve
 (done)    (active)
PLANNERS
 o Architect  Parity audit       01-parity.md     done
 o Engine     Plan-first mode    02-plan-mode.md  writing
 o Speed      Stalls, tabs       03-speed.md      writing
 o Designer   UI spec            04-ui.md         done
REVIEW
[card] Reviewer          (Changes needed)
       T1  Respect main_auto_continue
FINAL PLAN
[card] 12 tasks in 3 waves
       [Approve plan]   Ask for changes
```

- Stepper: 4 labels 12/16 joined by 1 px hairlines. Done = success dot, active = accent dot
  and text color, upcoming = faint ring. Labels never wrap.
- Planner row: dot, role, topic, plan file in mono, state word right. Click shows a
  read-only preview inline (max 12 lines, then "Open in editor").
- Review card: verdict pill (`Approved` success / `Changes needed` warning), then task rows
  (ID in mono, title, depends on).
- Final plan card: task and wave count; the view's only primary button "Approve plan", plus
  ghost "Ask for changes". After approval the stepper shows Running and links to Live.
- Empty: "No plan in progress" + ghost "Start a planning round" (goes through the local
  NotionTool delegate API; never creates Notion agents).

### 5.3 Ops (old-app features)

One scrolling list of collapsible sections in this order. Each shows at most 5 rows; "Show
all (n)" opens the full list in the same view with a back arrow in the title row.

| Section | Row content | Row actions (hover/focus) | Section action |
|---|---|---|---|
| Problems | severity dot, short title, source (mono), age | Open, Dismiss | count in title |
| Runs and reports | run name, `n of m` tasks, verdict pill, age | Open report (inline, read-only) | Active / All filter |
| Accounts | email, state dot (ready, signing in, error), active marker | Make active, Sign in again | Add account (ghost) |
| MCP servers | name, dot (connected, error, off), tool count | switch, Reconnect | Add server (ghost) |
| Git | branch (mono), ahead/behind, changed files; worktree rows: task id, files changed | none | Commit / Push (secondary, inline confirm) |
| Backups | path (mono, ellipsis on the left), time | Restore (inline confirm), Show diff | Open backup folder |
| Notes | existing notes view embedded | existing | existing |

- Problems is first and expanded; others are collapsed by default unless they have an error.
- Ops badge = open problems only. Account and MCP errors also create a problem, so there is
  one number, not three.

### 5.4 Settings (gear)

Existing settings view in the layer with a 32 px title row and back arrow. Visual alignment
only (sections and rows use the components above); no key changes.

## 6. Numbers: one source, one place

| Number | Shown only in |
|---|---|
| Notion unread chats | Chat tab badge |
| Coworkers needing attention | Live tab badge |
| Running coworkers | Live > Coworkers section count |
| Main progress `n of m` | Main card |
| Plan items waiting for the user | Plan tab badge |
| Open problems | Ops tab badge (Problems section count is the same value) |

The bell shows a dot only. The brand row shows no numbers.

## 7. Layout details

- Header 40 px, padding 8: brand mark 20 px (gradient, radius 6) + "NotionTool" 13/20 600;
  Live pill 20 px (dot + "Live" / "Offline"); bell and gear as 24 px ghost icon buttons.
- Tab bar right under the header: margin 0 8 8, padding 4, surface background, radius 8.
- View layer: starts below the tab bar, left edge = sidebar left edge (never `left: 0` of the
  window), ends 8 px above the Notion footer row and never overlaps it.
- Scrollbar 6 px, thumb `rgba(255,255,255,.12)`, no track.
- Sidebar under 220 px: tab labels 11 px; under 200 px only icons (name in `title`).

## 8. Accessibility

- Tab bar `role=tablist`, tabs `role=tab` + `aria-selected`, roving tabindex (exists).
- Section headers are `button` elements with `aria-expanded`.
- Contrast: text on bg >= 12:1, muted >= 6:1, white on accent about 4.9:1.
- Status is never color only: every dot has an `aria-label`, the state word is in `title`.

## 9. Build order (implementation round)

1. Tokens: add `--nt-faint`, `--nt-accent-soft`; drop the gradient outside the brand mark.
2. Shared components in new `ui.js` / `ui.css` (section, row, card, dot, progress, button,
   pill, switch, empty, inline confirm).
3. Shell: tabs Chat | Live | Plan | Ops; gear opens Settings; Notes moves into Ops.
4. Live view from the Mains/Coworkers parts of `overlay.js`.
5. Ops sections, one per old-app feature, on the existing local API endpoints.
6. Plan view once the plan-mode state API from `02-plan-mode.md` exists.

## 10. Needs from the other plan files

- `01-parity.md`: for each old-app feature, the local API endpoint that its Ops section reads
  (problems, runs/reports, accounts, MCP servers, git, backups).
- `02-plan-mode.md`: a state endpoint with stage, planners (role, topic, file, state), review
  verdict and task rows, final plan (task count, waves) and an approve action.
- `03-speed.md`: Live adds no Notion reads; it only uses local state. If the store has no
  per-coworker "last change" time yet, the engine should record it.
